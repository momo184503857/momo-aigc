# 服务故障黑匣子与本地报警规格

- 日期：2026-10-01
- 状态：用户已选择组合方案并授权开发；本地实现，生产尚未安装或部署

## 目标与已确认约束

服务出现短时卡死时，独立发现异常，保存故障前后证据供事后排查。
第一版报警仅留在服务器，不发送飞书、邮件或其他外部通知。
不自动重启、部署、切换渠道，不修改任务、积分、密钥或数据库业务状态。
监控提供定位证据，不承诺每次能够确定具体代码根因。

## 开发默认值

- 独立进程每 5 秒并行检查本机 Node 存活端点、Nginx 入口、只读数据库检查（独立 Worker，100ms 锁等待、500ms 响应上限）；每项 2 秒超时，上一轮未结束不得重叠。
- 连续 3 轮失败触发事故，连续 3 轮成功标记恢复；同一事故只记录一次开启和一次恢复，持续异常仅更新有界现场记录。
- Node 每 5 秒保存事件循环延迟、利用率、CPU、内存、在途请求数量及最长等待时间。
- 请求耗时超过 3 秒或异常结束时保存诊断日志；数据库操作超过 200 毫秒、上游阶段超过 10 秒记录慢操作。正常高耗时生图仅记录，不直接判定全站故障。
- 黑匣子日志和事故包保留上限 7 天，合计预算 300 MiB；容量优先，旧记录可能提前轮转或清理，预算在采样轮次检查而非实时硬配额。Nginx 源诊断日志另由系统 logrotate 管理，不计入该预算。轮转、清理只能作用于专用监控目录。采集输出、单次事故包及事故频率必须有界。
- 建议服务器目录 `/var/log/momo-aigc-monitor/`，包括 `alerts.jsonl`、滚动指标和 `incidents/` 事故包；实现时支持本地临时目录覆盖。

## 项目结构与技术方案

沿用 Express + TypeScript + SQLite，不增加付费服务或新业务数据库表。
建议新增后端诊断模块 `server/src/utils/diagnostics.ts`，在 `server/src/index.ts` 的解析器与路由之前安装请求跟踪，并在退出时清理采样器。
独立探测程序放在 `scripts/`，服务器服务配置与安装说明放在 `ops/` 与 `docs/reference/`；最终文件名在实施计划中确定。

- 健康端点仅供回环访问；Nginx 必须拒绝公网访问，不能仅凭可伪造的转发请求头判定来源。
- 进程存活与数据库探测分离，记录各自耗时，SQLite 检查不得产生业务写入或长时间锁等待。
- 请求使用服务器生成的 request ID；记录路径、阶段、耗时、HTTP 状态、断开状态、任务号和渠道标识，不记录完整 URL 查询参数、请求体、提示词、图片或密钥。
- 上游阶段至少区分提交、轮询、结果转存、图片代理；中断、异常与结束都要清理在途计数。
- Nginx 添加独立诊断 access log，包含请求、连接后端、响应头与响应总体耗时；不改变现有业务超时参数。
- 独立程序有界收集资源、网络、连接、业务进程状态与脱敏诊断日志。不导出完整进程环境、命令行、PM2 环境或原始业务日志。
- 写盘失败不能导致业务请求失败；监控停止或磁盘满时需产生本地兜底诊断，不无限重试。
- 独立监控随服务器启动，并独立于业务 Node 生命周期；整机宕机期间无法写本地报警，外部探测不在本版范围。

代码风格沿用当前 TypeScript：单引号、无分号、显式类型；结构化日志示例：

```json
{"timestamp":"2026-10-01T15:12:45+08:00","event":"incident_open","incidentId":"example","reason":"backend_probe_timeout","consecutiveFailures":3}
```

时间统一保存带时区的 ISO 时间，事故摘要展示北京时间。

## 验证命令与策略

现有命令：

```bash
npm run check
npm run build:server
```

实施时新增确定性测试命令并在 runbook 中注明。验证必须覆盖：

1. 正常响应不误报；连续失败报警、持续失败去重、连续恢复关闭事故。
2. 本地模拟后端主线程阻塞时，独立监控仍能检测、落盘，恢复后记录事件循环延迟和请求等待。
3. 单一上游慢而本地健康时，不误判为全站卡死。
4. 请求正常结束、客户端断开、上游失败都无在途计数泄漏。
5. 日志脱敏、大小预算、保留期限、写盘失败和采集超时。
6. 健康端点公网不可访问；合法本机探测可访问。
7. 所有故障注入只在本地隔离测试中进行，不在生产阻塞、停进程或调用付费生图。

## 边界与交付

- 始终：保留已有改动，先本地验证，明确已验证及未验证内容。
- 先征得确认：范围变化；用户已授权组合方案本地开发，生产安装、Nginx 修改、后端重启及部署另需明确授权。
- 禁止：提交或推送未经要求的改动、自动修复业务状态、泄露凭据、以监控健康代替业务功能验收。
- 成功标准：本地故障注入形成可关联的报警、现场、恢复记录；服务器启用后能通过只读查看命令查询。未经生产安装验收不能宣称监控已上线。
