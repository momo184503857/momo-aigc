# 图片两档加载验收（2026-09-25）

## 已实现

- 展示固定为最长边 400px 的等比例缩略图；预览、下载、编辑和生图输入保留原图。
- direct 使用 Sharp 按需生成 WebP，质量 80，禁止放大，自动方向，透明保留，动图首帧；缓存位于 `server/data/thumbnails/v1`，不改原文件、不迁移数据库。
- 限制每进程同时处理 2 张，排队上限 32，同图并发合并，原图最大 50 MiB / 4000 万像素，拒绝越界路径和目录外软链接。
- OSS 标准 Bucket 域名使用固定处理参数；未知外链、自定义域名及签名地址不静默退回原图。失败占位可重试，已有预览入口仍指向原图。
- 覆盖模板、结果、任务、素材、上传小图、管理端、画布节点、对比图条、公共卡片；本地上传预览使用 Canvas 派生 WebP，不改上传 File。
- 去除时间戳重试；下载不再从 DOM Canvas 重新编码，优先获取原始响应字节。
- 本地图片长期缓存，动态 API 不共享缓存；部署文档补 HTML 重新验证和哈希静态文件长缓存。OSS 三个写入路径补缓存元数据。

## 执行结果

通过：`npm run check`、`npm run check:ui`、`npm run test:ui`、`npm run test:images`、`npm run build`、`npm run build:server`、`npm run test:images:browser`、`npm run test:ui:browser`、`git diff --check`。

新增离线测试验证：比例、小图不放大、透明、EXIF 方向、动图首帧、并发复用、原图不变、超限/损坏/缺失、路径安全、direct/OSS 地址解析、200/304 与错误 no-store。

浏览器以正式构建、独立 HTTP 服务和合成图片运行，不启动业务后端。模板与结果页验证：首屏不请求原图、滚动增量加载、单图预览、关闭移除原图、下载与源文件逐字节相同、失败不回退原图且可预览和重试、缓存命中。公共展厅验证本地 SVG 转 WebP 后预览原图。另通过已有 UI 浏览器回归（双入口、权限、明暗、三种宽度、弹窗焦点、文件选择器等）。

### 可复现流量对照

同一正式模板页面、390×800 视口、同一操作、20 张不同 URL 的 1600×1200 合成纹理 PNG。基线服务对缩略图地址返回原始文件字节，优化组返回真实缩略图；这是传输策略对照，不是旧版本线上测量。

| 场景 | 实际传输字节 |
|---|---:|
| 基线首屏（6 张原图字节） | 34,630,680 |
| 缩略图首屏（6 张） | 232,932 |
| 滚动后累计（12 张缩略图） | 465,864 |
| 普通重载（12 张缓存命中，另外 8 张此前未请求） | 310,576 |
| 模拟入口更新后重访（20 张缓存命中） | 0 |

完整本地结果和截图：`.ui-test-output/images/report.json`、`templates.png`、`results.png`（忽略目录，不提交）。合成纹理压缩收益不能外推为线上节省率。构建通过但仍有大于 500 kB 的分包提示，本次未扩大到打包优化。

## 未验证与发布边界

- 未连接真实 OSS/FC，没有验证真实 Bucket 的处理权限、格式行为（包括动图首帧）、缓存响应头及存量对象元数据。
- 未在目标 Linux 上安装 Sharp；已验证本机原生模块可用。目标需 Node.js 20.9+，单独执行 `npm ci` 和 `npm run test:images`，不可复制 macOS node_modules。
- 未部署、未改线上 Nginx/OSS/FC、未提交或推送；没有调用付费生图接口。仓库 Worker 变更不会自动更新线上 FC。
- 未逐页操作所有批量工具和画布业务流程；已替换展示入口并通过类型/构建，专项浏览器验收集中在模板、生成记录及公共组件。
- 真实账单与线上发布后的缓存效果仍需经单独授权发布后观察。历史 OSS 对象不批量改写；任意外链的缩略图代理不在本次范围。
