# 墨墨 AI 生图 UI 设计规范

本文档是本项目的前端 UI 设计基准。后续任何 AI 或开发者修改 Vue 页面、组件、样式、文案、交互状态时，都必须先阅读并遵循本文档。

本规范不是审美建议，而是可执行的设计标准。判断一个 UI 修改是否合格时，按顺序检查三层：信息结构层、交互流程层、视觉表达层。

## 1. 产品定位

墨墨 AI 生图是内部 AI 生图工作台，目标用户是需要反复生成、查看、下载、复用图片结果的运营或创作人员。

界面目标：

- 像专业工具，不像营销官网。
- 让用户快速完成生成任务，不让视觉装饰干扰操作。
- 让图片结果比任务 ID、时间戳、技术参数更突出。
- 让状态明确：能不能生成、为什么不能生成、生成到哪一步、生成后能做什么。

禁止方向：

- 大面积渐变、装饰插画、光斑、复杂背景。
- 为了“好看”增加无意义卡片、阴影、动效。
- 页面所有按钮同等醒目。
- 把任务 ID、接口状态、技术错误当成主要用户信息。

## 2. 三层设计方法

### 2.1 信息结构层

信息结构层决定“用户第一眼能不能看懂页面”。

执行顺序：

1. 定义页面主任务。
2. 列出用户完成主任务需要的信息。
3. 按重要性排序。
4. 决定哪些常驻、哪些折叠、哪些放更多菜单。
5. 删除或弱化不支持当前任务的信息。

工作台页面的信息优先级：

| 优先级 | 信息 | 展示要求 |
| --- | --- | --- |
| P0 | 当前生成动作 | 生成按钮、必填输入、不能生成原因必须清楚 |
| P1 | 图片输入和图片结果 | 缩略图、上传区、结果图应比任务 ID 更显眼 |
| P1 | 生成状态 | 生成中、成功、失败、耗时、进度必须易扫读 |
| P2 | 复用动作 | 重新生成、下载、复制参数、查看详情 |
| P3 | 技术元信息 | 任务 ID、模型、尺寸、时间戳，默认弱化 |
| P4 | 管理工具 | 筛选、批量操作、分页、视图切换 |

执行标准：

- 页面第一眼必须能判断当前页面是“生图工作台”。
- 一个主要区域内只能有一个最强主按钮。
- 任务列表中，图片和状态优先于任务 ID。
- 低频动作不能长期占据高视觉权重位置。
- 每个区域都必须有清楚标题，但标题不要过大。
- 如果一个区域有 5 个以上操作，必须分主操作和更多操作。

当前工作台案例：

- 正确：左侧全局导航负责模块入口，中间表单负责生成，右侧任务列表负责结果和历史。
- 需要改进：任务卡片中任务 ID 太靠前，红色删除按钮太醒目，任务操作按钮太多。
- 推荐调整：任务卡片主行展示缩略图、状态、提示词摘要；任务 ID 放到次级信息或详情里；每条任务只常驻“重新生成”“下载”，其余进入“更多”。

### 2.2 交互流程层

交互流程层决定“用户会不会用、能不能顺利完成任务”。

核心路径：

选择功能 -> 填写提示词/参数 -> 上传或选择参考图 -> 点击生成 -> 等待状态更新 -> 查看结果 -> 下载或复用。

每一步必须有明确反馈：

| 步骤 | 用户问题 | UI 必须回答 |
| --- | --- | --- |
| 进入页面 | 我从哪里开始？ | 默认选中常用功能，生成表单可直接操作 |
| 填参数 | 还缺什么？ | 必填项、缺失项、限制条件清楚 |
| 不能生成 | 为什么按钮不能点？ | 按钮旁或提示条说明原因 |
| 点击生成 | 是否提交成功？ | 新任务立即出现在列表顶部 |
| 生成中 | 现在到哪一步？ | 状态、耗时、进度或排队文案 |
| 生成成功 | 下一步做什么？ | 查看、下载、重新生成、复制参数 |
| 生成失败 | 怎么恢复？ | 失败原因 + 重试/复制参数动作 |

执行标准：

- 禁用按钮必须有原因，不允许只有灰色禁用态。
- 生成后必须立即产生可见反馈，不等待接口完全结束才更新 UI。
- 成功状态的主动作优先级：查看大图 > 下载 > 重新生成 > 复制参数。
- 失败状态的主动作优先级：复制参数/重新生成 > 查看详情。
- 删除、禁用、清空等危险操作必须二次确认。
- 批量模式必须改变页面标题或工具栏状态，明确“已进入批量选择”。
- 可点击图片必须有 hover 效果，例如遮罩、放大图标或 cursor pointer。

当前工作台案例：

- 正确：已支持生成后进入任务列表、轮询状态、重新生成、下载、复制参数。
- 需要改进：生成按钮禁用时原因不够直接；图片点击查看不够明显；批量模式与普通模式的视觉差异还可以更强。
- 推荐调整：在生成按钮上方增加一行状态说明，例如“缺少 ToAPIs API Key，设置后即可生成”；任务缩略图 hover 时显示“查看大图”。

### 2.3 视觉表达层

视觉表达层决定“界面是否专业、现代、可信”。

视觉方向：

- 背景安静。
- 内容清楚。
- 图片突出。
- 操作克制。
- 状态明确。

执行标准：

- 不使用超过 1 个主色。
- 同一页面内字号不超过 4 个层级。
- 同类按钮样式必须一致。
- 卡片圆角、输入框圆角、按钮圆角必须来自同一套 token。
- 阴影只用于浮层、弹窗、主容器，不用于每个小控件。
- 分割线使用浅灰，不使用深色粗线。
- 页面不能出现中文乱码、半截文案、英文开发占位。

## 3. 视觉参数

### 3.1 字体

使用系统字体，不额外引入字体文件。

```css
font-family: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI",
  "Microsoft YaHei", "PingFang SC", "Hiragino Sans GB", Arial, sans-serif;
```

字号标准：

| 场景 | 字号 | 行高 | 字重 |
| --- | --- | --- | --- |
| 页面标题 | 22px | 30px | 600 |
| 区块标题 | 16px | 24px | 600 |
| 表单标签/正文 | 14px | 22px | 400 |
| 辅助信息 | 12px | 18px | 400 |
| 按钮文字 | 14px | 20px | 500 |

使用规则：

- 页面标题只用于顶部标题，例如“生图工作台”。
- 区块标题用于“生成参数”“任务列表”。
- 任务 ID、时间、耗时、尺寸使用 12px。
- 不允许用 18px、20px 随意新增标题层级。
- 不使用负 letter-spacing。

### 3.2 颜色

主色使用蓝色，保持和 Element Plus 当前风格兼容。

| 语义 | 颜色 | 用途 |
| --- | --- | --- |
| Primary | `#409EFF` | 主按钮、选中态、链接、关键图标 |
| Primary Hover | `#66B1FF` | 主按钮 hover |
| Primary Light | `#ECF5FF` | 选中背景、轻提示背景 |
| Success | `#67C23A` | 已完成、成功 |
| Warning | `#E6A23C` | 排队、生成中、注意 |
| Danger | `#F56C6C` | 删除、失败、危险动作 |
| Page BG | `#F5F7FA` | 页面背景 |
| Surface | `#FFFFFF` | 主内容面板、表单区 |
| Subtle Surface | `#F8FAFC` | 任务卡片、浅层分组 |
| Border | `#E4E7ED` | 分割线、输入框边框 |
| Border Light | `#EBEEF5` | 次级分割线 |
| Text Primary | `#1F2937` | 标题、主要正文 |
| Text Regular | `#606266` | 普通正文 |
| Text Secondary | `#909399` | 辅助信息 |
| Text Placeholder | `#A8ABB2` | 占位、弱信息 |

使用规则：

- 蓝色只用于当前选中、主按钮和可点击重点。
- 红色只用于失败和危险动作，不允许每条任务都长期暴露大红删除按钮。
- 页面背景不能纯白到底，主内容区用白色，外层用浅灰。
- 辅助信息不要用黑色。

### 3.3 间距

使用 4px 基准栅格。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--space-1` | 4px | 图标与文字内部间距 |
| `--space-2` | 8px | 小控件间距 |
| `--space-3` | 12px | 卡片内部紧凑间距 |
| `--space-4` | 16px | 区块内部标准间距 |
| `--space-5` | 20px | 页面内容 padding |
| `--space-6` | 24px | 大区块间距 |
| `--space-8` | 32px | 页面大段落间距 |

使用规则：

- 表单行垂直间距：16px 到 24px。
- 任务卡片内边距：12px 到 16px。
- 页面主内容 padding：20px 或 24px。
- 左右栏之间不要靠阴影区分，优先用 1px 分割线和 20px 内边距。

### 3.4 圆角

| 场景 | 圆角 |
| --- | --- |
| 输入框、按钮、小标签 | 6px |
| 任务卡片、上传框、模板卡片 | 8px |
| 主内容容器、弹窗 | 10px 到 12px |
| 圆形选择器、头像 | 999px |

使用规则：

- 不新增 16px、20px 以上的大圆角。
- 同一类组件圆角必须一致。
- 工具型页面不要使用过度圆润的“可爱风”圆角。

### 3.5 阴影

| 场景 | 阴影 |
| --- | --- |
| 主容器 | `0 8px 24px rgba(15, 23, 42, 0.08)` |
| 弹窗/浮层 | `0 16px 40px rgba(15, 23, 42, 0.16)` |
| 卡片 hover | `0 4px 12px rgba(15, 23, 42, 0.08)` |
| 普通卡片 | 不使用阴影，使用边框或浅背景 |

使用规则：

- 不给每个按钮、输入框、小卡片都加阴影。
- 任务卡片默认用浅背景或边框，hover 才轻微浮起。
- 分栏拖拽条不要使用发光阴影。

## 4. 工作台具体设计标准

### 4.1 整体布局

桌面端推荐结构：

| 区域 | 宽度 | 说明 |
| --- | --- | --- |
| 全局侧边栏 | 220px，折叠 64px | 模块入口 |
| 工作台功能导航 | 160px 到 180px | 生图功能切换 |
| 生成参数区 | 420px 到 620px | 当前任务输入 |
| 任务结果区 | 自适应 | 历史和结果 |

执行标准：

- 页面高度撑满视口，内部区域自己滚动。
- 生成按钮固定在生成参数区底部。
- 任务列表滚动不影响左侧导航和生成按钮。
- 右侧任务区宽度不足时，优先隐藏低级元信息，而不是压缩图片。

### 4.2 生成参数区案例

推荐信息顺序：

1. 区块标题：“生成参数”。
2. 参考图片：上传或从模板选择。
3. 提示词：主要文本输入。
4. 模型：默认给出推荐模型。
5. 分辨率：使用 segmented/radio button。
6. 宽高比：使用 select。
7. 生成数量：使用 select 或 stepper。
8. 生成按钮：固定底部。

禁用案例：

```text
生成图片 - ¥0.140
```

如果不可用，按钮上方必须出现原因：

```text
请先设置 ToAPIs API Key，设置后即可生成图片。
[生成图片 - ¥0.140] disabled
```

必填参考图缺失时：

```text
请上传参考图片后再生成。
```

### 4.3 任务列表案例

列表模式推荐结构：

```text
[缩略图]  [状态标签] 提示词摘要
          模型 / 尺寸 / 耗时 / 时间
          任务 ID：弱化显示，可复制
                                            [重新生成] [下载] [更多]
```

不要这样：

```text
[缩略图] 任务ID：tsk_xxxxxxxx 复制
        已完成 耗时 1分25秒 GPT-Image-2 1K / 1:1
                                            [重新生成] [详情] [下载] [复制参数] [删除]
```

原因：

- 任务 ID 抢占第一行。
- 常驻按钮过多。
- 删除按钮太醒目。
- 图片结果没有成为主角。

任务卡片执行标准：

- 缩略图最小 72px，推荐 80px 到 96px。
- 状态标签放在标题行靠前位置。
- 提示词摘要最多 1 到 2 行。
- 任务 ID 使用 12px、灰色、可复制。
- 常驻按钮最多 2 个。
- “详情、复制参数、复制 ID、删除”放入更多菜单。
- 删除在更多菜单中使用 danger 文案，并二次确认。

网格模式推荐结构：

```text
[大缩略图]
提示词摘要
[状态] 模型 / 尺寸
[下载] [重新生成] [...]
```

网格模式中图片必须占卡片高度 60% 以上。

### 4.4 筛选和批量操作

筛选区属于任务列表工具栏，不是页面主任务。

执行标准：

- 筛选控件使用 small 尺寸。
- 筛选控件视觉权重低于任务标题。
- 批量模式开启后，工具栏显示“已选择 N 项”。
- 批量模式下隐藏普通任务操作，只保留选择、批量下载、取消。
- 批量操作按钮不要使用多个 primary，只允许一个 primary。

## 5. 组件执行标准

### 5.1 按钮

| 类型 | 用途 | 样式 |
| --- | --- | --- |
| Primary | 当前最重要动作，例如生成 | 蓝底白字 |
| Secondary | 普通动作，例如详情、筛选 | 白底灰边 |
| Text/Icon | 复制、折叠、查看 | 透明或弱按钮 |
| Danger | 删除、禁用 | 默认不常驻，放更多菜单 |

规则：

- 一个主要区域只能有一个 primary 按钮。
- 同一组按钮高度必须一致。
- 图标按钮必须有 title 或 tooltip。
- 按钮文案不超过 6 个汉字，必要时用图标辅助。

### 5.2 表单

规则：

- 标签右对齐或左对齐必须全页面一致。
- 表单控件宽度同列对齐。
- textarea 最少 3 行，最多默认 6 行。
- placeholder 告诉用户输入什么，不写业务解释长句。
- 必填项缺失时在控件附近提示，不只依赖红色星号。

示例：

```text
提示词 *
[描述你想要生成的图片...]
0/32000
```

### 5.3 状态标签

| 状态 | 文案 | 颜色 |
| --- | --- | --- |
| submitted | 已提交 | info |
| queued | 排队中 | warning |
| in_progress | 生成中 | warning |
| completed | 已完成 | success |
| failed | 生成失败 | danger |
| unknown | 状态未知 | info |

规则：

- 用户态文案用中文。
- 不直接显示 `submitted`、`in_progress`、`unknown`。
- 失败状态必须展示可理解原因和恢复动作。

### 5.4 空状态

空状态必须包含三部分：

1. 当前没有什么。
2. 为什么会这样。
3. 用户下一步做什么。

示例：

```text
暂无生成任务
填写左侧参数并点击生成后，任务会显示在这里。
```

不要只写：

```text
暂无数据
```

## 6. AI 修改 UI 时的工作流程

AI 修改 UI 前必须先回答：

1. 这次修改主要影响哪一层：信息结构、交互流程、视觉表达？
2. 当前页面主任务是什么？
3. 哪个信息应该被突出，哪个应该被弱化？
4. 是否改变用户完成任务的路径？
5. 是否新增了颜色、字号、圆角、阴影？如果新增，为什么不能复用本规范？

AI 修改后必须检查：

- 主任务是否更清楚。
- 主按钮是否唯一。
- 禁用、加载、失败、空状态是否完整。
- 图片结果是否比技术元信息更突出。
- 危险操作是否被弱化。
- 字号、颜色、圆角、间距是否符合本规范。
- 中文是否无乱码、无半截标签、无开发占位。

## 7. 验收清单

每次 UI 改动完成后，逐项验收：

- 页面第一眼能看出这是哪个功能。
- 用户知道下一步该做什么。
- 用户不能继续时知道原因。
- 页面没有超过一个最强主按钮。
- 常驻按钮没有超过必要数量。
- 任务 ID、时间戳、技术参数被弱化。
- 图片、状态、主要动作被突出。
- 删除等危险操作不抢视线。
- 空、加载、失败、禁用、成功状态都有设计。
- 字号不超过 4 个层级。
- 主色只用于关键强调。
- 圆角、阴影、间距统一。
- 页面在 1366px 宽度下不重叠、不溢出。
- 页面在窄屏下优先保持核心任务可用。
