## 公共体系收口

- 公共主题独立维护语义颜色、字号、间距、圆角、状态及图表色；删除新库内部的旧变量桥接和变量自引用。
- 删除正式入口旧主题、后台独立旧皮肤、`legacy-surface` 及旧视觉基线文件。
- 页面滚动外壳提升为公共 `DsScrollPage`，保持 `.page-content` 观察根及滚动契约；搜索框、文件选择器进入公共组件，补齐展厅登记。
- `DsSearchInput` 统一图标与输入内边距；`DsFileInput` 保留 DOM change 和 click/value 重选契约；基础 Input 暴露 focus/select/element，保留任务备注编辑行为。
- `DsColorPicker` 增加预设与随机选择，画布项目颜色可键盘操作；用户选择的内容色与图片编辑器绘图色不按 UI 硬编码删除。
- 图表读取公共主题，节点使用公共语义色；画布节点通过公开 CSS 变量接入；引擎自带缩放控件替换为公共 DsCanvasControls，MiniMap 使用公共主题根样式，不用页面深层选择器覆盖引擎控件。
- 移除页面深层选择器、任意字号和控件颜色／圆角等视觉覆盖；危险按钮使用语义变体。
- 不改服务端、数据库、业务 API、计费、任务生命周期和存储入口。

## 开发原型例外

按用户要求忽略开发原型，`src/prototype/` 未修改。

旧组件原有 225 个文件，删除无原型引用的 208 个，仅保留原型实际引用的 17 个文件：button、input、textarea 和 dialog 组件族。没有复制兼容库。它们只供开发原型使用，正式源代码引用会被严格检查拒绝，生产构建依赖审计也会拒绝。

原型不列入此次功能／视觉验收。旧全局主题文件没有引用，已删除；不对原型视觉一致性作保证。

## 自动化验证

```bash
npm run check
npm run check:ui
npm run test:ui
npm run build
npm run test:ui:browser
npm run test:ui:phase-two
npm run test:ui:auth
npm run test:ui:prompts
```

- `check:ui` 不再读旧基线：正式代码零旧入口、零旧 Token、零存量豁免。画布内容色采用精确语义行匹配，不豁免整页。
- `build` 生成 `dist/ui-dependency-audit.json`；发现旧 UI、旧主题或原型模块即构建失败。
- `test:ui:phase-two` 依次执行原样板回归、30 个正式入口主题矩阵、专项操作回归。
- 全量入口：18 个用户端、6 个独立后台、6 个内嵌后台；每入口覆盖 2 种主题 × 2 种密度 × 4 种宽度（320/768/1024/1440），共 480 个布局组合，另测空数据与失败夹具。
- 所有 API 请求均在浏览器内拦截，不发送真实业务写入。测试使用安装的 Chrome，通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright。
- 建议针对生产预览运行，避免开发服务器 HMR 打断测试：`UI_TEST_URL=http://127.0.0.1:5373`。

上述命令已执行通过；最终公共组件登记为 94 项。生产依赖审计记录 805 个源模块，旧组件／原型模块命中为零。
