# 模型统一售价与渠道自动路由 · 功能方案（草案）

> 状态：已确认，2026-09-02 开始实现。

## 1. 目标

用户前台只感知平台定义的逻辑模型，不展示或选择渠道。用户选择模型、分辨率和宽高比后，服务端从支持该参数组合的渠道模型中按成本价从低到高尝试；一个渠道失败后自动尝试下一个，全部失败时任务失败并全额退款。

管理员分别维护：

- 渠道模型成本价：渠道 × 逻辑模型 × 分辨率，用于内部路由排序，不向普通用户公开。
- 逻辑模型售卖价：逻辑模型 × 分辨率，用于前台统一展示和积分结算，不随实际命中的渠道变化。

成功标准：相同逻辑模型和分辨率在所有前台入口只显示一个售价；请求优先命中最低成本的可用渠道；渠道切换不重复扣款、不创建多个用户任务；全部候选失败后只产生一次全额退款。

## 2. 核心概念与数据口径

### 2.1 模型

普通用户选择 `ai_logical_models` 表示的逻辑模型。`ai_models` 继续表示某个渠道对该逻辑模型的上游映射，包含上游 `model_id`、能力覆盖和启停状态。

### 2.2 价格

| 配置项 | 归属 | 粒度 | 用途 | 用户可见 |
|---|---|---|---|---|
| 售卖价 `sale_pricing` | 逻辑模型 | 分辨率 | 余额校验、预扣、按钮与计费说明展示 | 是，积分/张 |
| 成本价 `cost_pricing` | 渠道模型 | 分辨率 | 候选渠道排序、内部核算 | 否，人民币元/张 |

生图任务按 `sale_pricing[分辨率] × n` 预扣。实际执行渠道变化不补扣、不退差价。所有渠道均失败时按原流水全额退款。

### 2.3 候选渠道

一个渠道模型进入候选列表必须同时满足：

1. 渠道、渠道模型和逻辑模型均为启用状态。
2. 渠道模型关联用户所选逻辑模型，并支持生图。
3. 生效能力支持请求的分辨率、宽高比、参考图数量和提示词长度。
4. 请求分辨率已配置有效成本价。
5. 渠道至少有一把可用 Key。

候选按成本价升序排列；成本相同时按渠道模型 ID 升序，保证路由稳定且可复现。

## 3. 用户流程

1. `GET /api/models/catalog?kind=image` 返回逻辑模型列表、逻辑能力和统一售卖价，不返回渠道名称、渠道模型 ID、适配器或成本价。
2. 用户选择逻辑模型、分辨率和宽高比，前端提交 `logicalModelId`。
3. 服务端校验统一售价和参数，按统一售价预扣并创建内部任务。
4. 服务端解析候选渠道，按成本价从低到高派发。
5. 每个渠道每次只使用按现有优先级选出的第一把可用 Key；该 Key 调用失败后不尝试同渠道的其他 Key，直接进入下一渠道。
6. 任一渠道成功后，任务绑定实际渠道模型、渠道、Key 和渠道侧任务号，继续状态轮询与结果转存。
7. 所有候选渠道失败后，任务进入 `failed`，记录最后错误和完整路由尝试记录，并全额退款。

## 4. 失败切换规则

### 4.1 会切换下一渠道

- 同步渠道的上游调用抛错或返回无图片。
- 异步渠道提交阶段报错。
- 异步渠道已受理，但后续查询明确返回业务失败终态。
- 当前渠道在执行前已无可用 Key。

同一任务在同一渠道最多发起一次上游调用。渠道内即使配置了多把启用 Key，也不执行请求内 Key 轮换；其他 Key 仅供管理员调整优先级或手动切换主 Key 后用于后续新任务。

异步渠道进入失败终态后切换时，复用同一内部任务和原始业务参数，清空当前渠道侧任务绑定，再派发下一候选渠道。

### 4.2 不切换渠道

- 请求在进入路由前的本地参数校验失败。
- 用户余额不足。
- 参考图上传失败或服务端无法读取输入文件。
- 上游已经成功出图后的本站存储转存失败；沿用“重新加载/重新转存”。
- 客户端轮询请求本身的网络错误。

### 4.3 尝试记录

新增路由尝试记录，每次尝试至少保存：任务 ID、顺序、渠道模型 ID、渠道 ID、Key ID、成本快照、开始/结束时间、结果、错误码和脱敏错误摘要。普通用户只看到当前任务状态和最终错误；管理员可查看完整链路。

## 5. 管理后台

### 5.1 渠道与渠道模型

- 渠道和 Key 继续只允许管理员配置。
- 一个渠道可以保存多把 Key，但运行时只取优先级最高的启用 Key；该 Key 失败时直接切换渠道，不自动尝试该渠道的下一把 Key。
- 渠道模型的原“定价”改名为“成本价”，按其生效分辨率逐项必填。
- 成本价仅用于路由，不进入用户积分流水。
- 渠道模型未关联逻辑模型、能力无效或成本价缺档时不能启用生图。

### 5.2 逻辑模型

- 逻辑模型增加“售卖价”配置，按逻辑模型能力中的分辨率逐项必填。
- 生图逻辑模型缺少任一分辨率售价时，不进入用户模型目录。
- 售价修改只影响修改后创建的任务；任务保存售价和扣费快照，历史流水不变。

## 6. API 与兼容

- 模型目录由“按渠道分组的渠道模型”改为“逻辑模型列表”。
- 生图提交主参数由 `channelModelId` 改为 `logicalModelId`。
- 迁移期可短期接受旧 `channelModelId`：解析其逻辑模型后仍进入统一路由，不保证继续命中原渠道；前端代码全部改为新参数。
- 历史任务保留原 `channel_model_id`、`channel_provider_id` 和展示信息。
- 新任务在路由成功后写入实际命中的渠道信息；失败任务保留最后一次尝试，并可通过尝试记录追溯全链路。

## 7. 工程位置与约束

主要代码位置：

- `server/src/routes/generations.ts`：统一计费、候选路由、派发、轮询和退款。
- `server/src/utils/channelModel.ts`：逻辑模型能力与候选渠道解析。
- `server/src/routes/models.ts`：面向用户的逻辑模型目录。
- `server/src/routes/admin/aiConfig.ts`：成本价与售卖价管理 API。
- `src/stores/modelCatalog.ts`：前端逻辑模型目录。
- `src/services/imageGeneration.ts`：统一提交参数。
- `src/views/admin/AdminAiConfig.vue`：成本价、售卖价配置界面。

实现遵循现有 TypeScript 风格、`--momo-*` 样式变量和 `useUiFeedback`；不新增依赖，不在用户 API 中暴露渠道与成本。

## 9. 边界

- 必须：路由和扣退费均在服务端完成；价格保存快照；切换保持幂等；错误日志脱敏；一个用户请求只对应一组内部业务任务；同一任务不在单个渠道内轮换 Key。
- 已确认：暂不做失败渠道的自动暂停或冷却；后续任务仍按实时成本排序重新尝试。
- 不做：按用户定制售价、动态加价率、随机/权重路由、跨任务成本预算、自动修改管理员配置。

## 10. 已定口径

1. 成本价采用人民币元/张，售卖价采用积分/张。
2. 异步渠道已经接单、后续明确失败时继续切换下一个渠道；网络超时等无法确认上游是否接单的情况不跨渠道，避免重复生成。
3. Key 失败后不自动暂停渠道；同一任务直接切换下一渠道，后续新任务仍从最低成本渠道开始。
