# 固定渠道与多 Key 轮换 · 功能方案（fixed-channels）

> 业务域代号：`fixed-channels`。本文档是「渠道固定化 + 平台渠道多 Key 优先级轮换」的产品需求方案（**已实施**，2026-08-21 交付）。
> 核心内容：下线用户自建渠道（我的渠道）体系、渠道收敛为管理员配置的平台共用渠道、一渠道多 Key 优先级池、Key 欠费自动切换、计费口径统一。
> 配套文档：技术方案 `docs/design/fixed-channels-tech.md`，测试文档 `docs/reference/fixed-channels-test-plan.md`，验收标准 `docs/requirements/fixed-channels-acceptance.md`，迁移与上线 `docs/design/fixed-channels-migration.md`。
> 前置背景：本方案是对 `docs/requirements/ai-provider.md`（多渠道体系）的**回退与增强**——ai-provider 中的用户自建渠道（FR5、D7/D8/D9 等）随本方案废止。

---

## 1. 背景与目标

### 1.1 现状问题

ai-provider 重构上线了「平台渠道 + 用户自建渠道」双轨体系，实际运营后暴露以下问题：

| # | 问题 | 现状位置 |
|---|------|---------|
| P1 | 渠道 Key 单点：每渠道只有一把「主 Key」，上游欠费/耗尽后渠道整体不可用，所有生图任务连环失败 | `api_provider_keys.is_primary` 部分唯一索引；`resolveProviderContext` 只取主 Key |
| P2 | 用户自建渠道与产品定位冲突：运营方希望模型与算力统一由平台供给，不希望用户自带 Key | 「我的渠道」页 + `/api/my/*` 全套 |
| P3 | 用户渠道扩大安全与维护面：用户 base_url 的 SSRF 校验、用户 Key 加密存储、明文/密文双轨 | `myChannels.ts`、`utils/ssrf.ts`、`crypto.ts` 双轨 |
| P4 | 计费双轨复杂：用户渠道免计费（D8）分支渗透到提交、目录、前端约 12 个组件，模型选择器需区分「平台/个人」 | `generations.ts` isPlatform 分支、`modelCatalog.ts` mine 逻辑 |
| P5 | 遗留个人 Key 体系（`user_toapis_keys` + `resolveUserApiKey`）仍残存半套 | `me-toapis-key.ts`、`me.ts` personalKeyCredits |

### 1.2 目标

| 目标 | 衡量标准 |
|------|---------|
| 渠道固定化 | 全站不再有用户自建渠道入口；所有生图/文字调用走管理员配置的平台共用渠道 |
| Key 池 | 管理员可给一个渠道配置多个 Key，数字优先级排序（小者优先），无需改代码 |
| 欠费自动切换 | 某个 Key 被上游判定欠费/额度耗尽时，本次请求自动切换到下一个可用 Key 重试，用户无感 |
| 耗尽可恢复 | 已耗尽 Key 在管理端可见、可手动重新启用（充值后），恢复即参与轮换 |
| 计费统一 | 所有模型按平台定价扣积分、失败自动退款；废止「个人渠道不扣积分」双轨 |
| 存量平滑清理 | 升级自动迁移：用户渠道删除、遗留个人 Key 表清理，历史任务展示不受影响 |

### 1.3 非目标（本期不做）

- 不做渠道级自动路由（多渠道间故障切换、按价格择优）——Key 轮换仅发生在**同一渠道内**。
- 不做耗尽 Key 的定时余额复检与自动恢复——恢复只由管理员手动触发（F4）。
- 不做 401/403（Key 失效/被封）的自动跳过——仅欠费信号触发切换，避免把临时性鉴权错误误判为永久失效。
- 不做 Key 级用量统计 / 成本对账（后续演进）。
- 不改协议适配器清单与逻辑模型体系（沿用 ai-provider 现状）。

## 2. 术语表

| 术语 | 定义 |
|------|------|
| 平台渠道 / 固定渠道 | 管理员在后台配置的共用渠道（base_url + 协议适配器 + Key 池），全体用户可用。本方案后「渠道」即指平台渠道 |
| Key 池 | 一个渠道下的全部 API Key 集合，每个 Key 带优先级与状态 |
| 优先级（priority） | 正整数，**数字越小越先用**（1 最先）。同优先级时按录入先后（id）排序 |
| 可用 Key | 状态为 active 的 Key。调用时取优先级最高的可用 Key |
| 耗尽（exhausted） | Key 的历史状态（旧版自动标记）。2026-08 起服务端**不再写入**——项目无权因上游报错停用（拦截）用户的 Key；存量耗尽 Key 可由管理员「重新启用」，此后该状态不再产生 |
| 配额/欠费信号 | 上游返回的配额或余额类报错：HTTP 402/429，或 400/403 且文案含「余额 / 欠费 / quota / 额度 / 次数 / rate limit / 频繁 / 用完」等。仅用于决定**本次请求**是否换下一个 Key 重试，不落库、不冷却、不影响后续请求 |
| 切换（failover） | 命中配额/欠费信号后：**仅本次请求**换下一个可用 Key 重试；不标记、不停用任何 Key。试遍全部 Key 仍失败时，把**上游最后一次的原始报错**透传给用户 |
| 全部耗尽 | （历史概念）渠道所有 Key 均为耗尽/停用状态、无可用 Key；现为纯配置问题，任务失败并全额退款 |

## 3. 已确认决策记录

以下决策已与需求方确认，作为本方案与配套技术方案的基准：

| # | 决策点 | 结论 |
|---|--------|------|
| F1 | 渠道固定化 | 下线「我的渠道」整套功能（页面、API、菜单、余额展示）；渠道只由管理员配置 |
| F2 | Key 池模型 | 一渠道多 Key，正整数优先级（小者优先）；调用取 `priority ASC, id ASC` 的第一个可用 Key |
| F3 | 配额/欠费判定与切换 | **项目无权停用用户的 Key**：命中配额/欠费信号（402/429，或 400/403 且文案含 余额/quota/额度/次数/频繁 等）→ 仅**本次请求**换下一个可用 Key 重试，不写库、不冷却；试遍仍失败则把上游**原始报错透传给用户**（任务失败 + 全额退款），用户自行决定等额度/充值/换 Key；适用生图（异步提交、同步执行）与文字调用 |
| F4 | 恢复方式 | 服务端不再自动标记耗尽（2026-08 修订）；存量 exhausted Key 可由管理员手动「重新启用」（清耗尽标记、恢复 active），此后 exhausted 不再产生 |
| F5 | 计费统一 | 废止 D8（用户渠道免计费）：所有渠道模型按平台定价预扣积分、失败自动退款 |
| F6 | 存量处置 | 升级迁移删除全部用户渠道及其模型/Key（迁移前自动备份）；DROP 遗留表 `user_toapis_keys` |
| F7 | Key 存储沿用 | 平台渠道 Key 明文存储（`key_iv` 空）、管理端可查看复制——沿用 T6 之后的现状，不回退为加密 |

### 3.1 补充默认决策（实现期按此执行，可复核调整）

| # | 决策点 | 默认结论 | 说明 |
|---|--------|---------|------|
| S1 | 新 Key 默认优先级 | 该渠道现有最大优先级 + 1（首个 Key 为 1），即默认排到最后 | 管理端可随时改 |
| S2 | 优先级允许重复 | 允许；同优先级按录入先后（id 升序）稳定排序 | 避免唯一性校验的维护成本 |
| S3 | 轮询路径不切换 | 异步任务的状态轮询出错维持现状（记警告、下轮重试），不触发 Key 切换 | 任务已在上游，换 Key 也无济于事；避免误判 |
| S4 | 耗尽 Key 不可编辑优先级 | 耗尽状态下仅允许「重新启用」或「删除」；重新启用即视为可再参与轮换 | 简化状态机，见 §5 FR2 |
| S5 | 停用（disabled）语义沿用 | 管理员手动停用的 Key 不参与调用、不显示为耗尽；启用后恢复参与 | 与现有 keys 管理一致 |
| S6 | `/api/my/*` 下线方式 | 路由整体卸载返回 404（前后端同版本发布，无过渡期）；如生产存在旧前端缓存页，可选保留一个版本返回 410 | 见技术方案 §5.3 |

## 5. 功能需求

### FR1 渠道管理瘦身（管理员）

1. 渠道列表、CRUD、测试连通、启停**沿用现状**；渠道 = base_url + 协议适配器 + Key 池（不再提「主 Key」）。
2. 管理端删除用户渠道相关的全部入口：用户自建渠道只读 Tab（S1 of ai-provider）下线。
3. 渠道卡片上的「主 Key hint」改为「首个可用 Key hint」+ Key 总数（如 `Keys 3 · sk-a1**…`），无可用 Key 时醒目提示。

### FR2 Key 池管理（管理员）

1. 一个渠道下可配置任意多个 Key；列表按优先级升序展示。
2. Key 字段：名称、Key 值（明文存储、表格内可见可复制，沿用现状）、**优先级**（正整数）、状态（`active` 启用 / `disabled` 停用 / `exhausted` 已耗尽）、最近检测时间与结果。
3. 新增 Key：默认优先级 = 当前最大 + 1（S1），可修改；不提供「设为主 Key」概念。
4. 编辑 Key：改名、轮换 Key 值、修改优先级（仅 active/disabled 状态可改优先级，S4）、启停。
5. **耗尽态展示与恢复**：状态列对 exhausted 显示红色「已耗尽」标签（含耗尽时间），操作列提供「重新启用」——确认后状态恢复 active、清空耗尽标记，立即重新参与调用。
6. 删除 Key：直接删除；不再有「删除主 Key 自动提升下一个」的逻辑（Key 选取本来就是动态按优先级取）。
7. 测试连通：沿用单 Key 测试（`POST /keys/:id/test`）；渠道级测试使用**优先级最高的可用 Key**。

### FR3 配额/欠费报错的换 Key 重试（服务端，不拦截用户 Key）

> 2026-08 修订：渠道为用户自配 API，**项目无权因上游报错停用/拦截任何 Key**。原「自动标记 exhausted」机制移除。

1. **判定信号**（F3）：HTTP 402（欠费）/ 429（限流：每日额度、频率限制等），或 400/403 且错误文案含 余额/欠费/quota/额度/次数/rate limit/频繁/用完 等（部分中转站把配额用完报成 400「insufficient quota」）。其他错误（含 401 鉴权失败、5xx、网络超时）不触发轮换。
2. **切换流程**：命中信号 → **仅本次请求**按优先级换下一个可用 Key 重试；不写库、不冷却、不停用——每个新请求始终从优先级最高的可用 Key 开始。单 Key 渠道退化为直接把上游报错透传给用户。
3. **失败出口**：试遍全部 Key 仍失败 → 任务 failed（错误码 `UPSTREAM_ERROR` / `SUBMIT_FAILED`），**error_message 为上游最后一次的原始报错**（逐字透传，如「You exceeded your current quota」「今日额度已用完」），已预扣积分**全额自动退款**。额度恢复/充值后无需任何操作即可继续使用。渠道本就无可用 Key（全部停用/未配置，纯配置问题）→ `ALL_KEYS_EXHAUSTED` + 退款。
4. **适用范围**：异步渠道任务提交（toapis）、同步渠道生图执行（openai_image / volcengine_image）、画布文字 AI 调用（openai_compat / toapis chat）。
5. **不适用**：异步任务状态轮询、结果转存（S3——这些路径的错误不影响任务终态，沿用现状的瞬时容忍）。
6. **用户可见性**：轮换过程对用户完全透明；失败时用户在任务面板看到**自己 API 返回的原始错误信息**，自行决定如何处理。

### FR4 计费统一

1. 所有渠道模型（全部为平台渠道）生图按 `ai_models.pricing[分辨率] × n` 预扣积分；不足返回 402、任务不创建（沿用现有交互）。
2. 任务失败（含全部耗尽）自动全额退款并写 refund 流水；completed 不回退（沿用现状）。
3. 废止「用户渠道模型费用为 0 / 不扣积分 / 跳过余额预检」的全部逻辑与文案。
4. 生图表单按钮恢复统一文案：`生成图片 · X 积分（≈¥Y）`；不再出现「个人渠道 · 不扣积分」。

### FR5 模型目录与选择器简化

1. `GET /api/models/catalog` 响应去掉 `mine` 字段，仅返回平台渠道分组；前端 `modelCatalog` store 同步删除 mine 概念（分组置顶、默认模型偏好、参考价折算等）。
2. 模型下拉只显示平台渠道分组；选项不再有「（个人）」后缀与「我的渠道 ·」前缀。
3. 默认模型 = 目录第一个可用模型（不再优先 mine）。
4. 「暂无可用模型」提示统一为「请联系管理员配置渠道与模型」。

### FR6 用户侧下线清单

| 对象 | 处置 |
|------|------|
| 「我的渠道」页面（`/my-channels`）与侧边栏菜单项 | 删除 |
| 侧边栏左下角「Key 余额」行与轮询 | 删除（Key 不再属于用户） |
| 「我的额度」页的我的渠道入口卡片与相关统计 | 删除；积分区不变 |
| 「计费说明」页的「我的渠道不扣积分」区块 | 删除 |
| 各生图表单 / 批量工具 / 买家秀 / 画布节点的 `isPersonalChannel`、余额预检跳过、个人渠道文案 | 全部移除，统一走平台计费 |
| `personalKeyCredits`（我的额度接口遗留字段）与旧个人 Key 端点 | 删除 |

### FR7 管理端可见性与告警

1. Key 表展示耗尽状态与耗尽时间；渠道维度可直观看到「可用 / 耗尽 / 停用」分布。
2. 渠道卡片在**无可用 Key**（全部耗尽或停用）时给出醒目警示（该渠道下所有模型实际不可用）。
3. 任务失败原因（含 `ALL_KEYS_EXHAUSTED`）在管理端任务列表/详情可查，便于定位是哪类问题。

### FR8 存量迁移（升级自动完成，用户无感）

1. 删除全部用户自建渠道及其渠道模型、Key（历史任务先做外键置空，任务记录与展示不受影响）。
2. 现有主 Key 迁移为优先级 1，其余 Key 优先级 100（保持原有序语义）。
3. DROP 遗留表 `user_toapis_keys`；清理 `resolveUserApiKey` 等遗留代码引用。
4. 迁移幂等（标记位控制）、执行前自动全库备份，失败中止启动；明细见迁移手册。

## 6. 关键用户旅程

### 6.1 管理员：给 ToAPIs 渠道配 Key 池

1. 管理后台 →「配置」→ ToAPIs 渠道 → Key 管理：已有主 Key（迁移后优先级 1）。
2. 「新增 Key」：名称「备用-充值卡A」、粘贴 Key、优先级默认 2 → 保存 → 测试连通通过。
3. 日常调用始终走优先级 1 的 Key；它欠费耗尽后自动切到优先级 2。

### 6.2 Key 耗尽 → 自动切换 → 充值恢复（核心旅程）

1. 某用户提交生图，服务端用优先级 1 的 Key 调 ToAPIs，上游返回 `402 余额不足`。
2. 服务端把该 Key 标记「已耗尽」（管理端立即可见），随即用优先级 2 的 Key **重试同一请求** → 成功，任务正常进行；用户全程无感。
3. 管理员看到耗尽标签 → 去上游充值 → 回到管理端点「重新启用」→ 该 Key 恢复参与轮换（因优先级仍最小，下一次调用即回到它）。
4. 若两个 Key 同时耗尽：任务标 failed、错误码 `ALL_KEYS_EXHAUSTED`、积分自动全额退款；管理端渠道卡片显示无可用 Key 警示。

### 6.3 普通用户：平台模型生图（与现状一致）

1. 模型下拉按渠道分组选模型 → 按钮显示价格 → 提交 → 4s 轮询 → 结果转存 OSS。
2. 唯一变化：界面不再出现「我的渠道 / 个人渠道」任何入口与文案；计费规则统一。

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | Key 切换不增加用户可感延迟（切换为服务端内部逐 Key 重试，单次上限 = 渠道 Key 数）；Key 选取为单行索引查询，提交接口耗时不受影响 |
| 可靠 | 切换过程不丢任务、不重复扣费：预扣发生在派发前，失败路径统一走退款；并发耗尽标记幂等 |
| 安全 | Key 明文仅管理端可见（沿用现状）；用户侧任何接口不回显 Key；欠费切换不改变出站调用路径（仍由服务端发出） |
| 兼容 | 历史任务/作品/积分流水/统计口径不变；works、买家秀、批量工具、画布等下游不感知 |
| UI 约束 | 管理端 Key 表改造遵循 `--momo-*` token 体系与 `useUiFeedback`；下线功能以删除为主，不新增用户侧页面 |
| 可运维 | 耗尽事件留服务端日志（渠道、Key id、上游错误摘要），便于与上游账单对账 |
