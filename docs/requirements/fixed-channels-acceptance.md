# 固定渠道与多 Key 轮换 · 验收文档（fixed-channels）

> 对应功能方案 `docs/requirements/fixed-channels.md`、技术方案 `docs/design/fixed-channels-tech.md`、测试文档 `docs/reference/fixed-channels-test-plan.md`、迁移手册 `docs/design/fixed-channels-migration.md`（已实施）。
> 级别定义：**S = 必须通过（阻断发布）**；A = 应当通过（次回合补齐）；B = 建议（记录跟踪）。
> 欠费切换类用例依赖 mock 上游（测试文档 §2.1）做确定性构造；标注「mock」的用例不依赖真实上游欠费。

---

## 1. 验收范围与环境

### 1.1 模块划分

| 模块 | 范围 |
|---|---|
| M1 渠道固定化与存量迁移 | 用户渠道下线（API/数据）、/api/my/* 退役、T7 迁移正确性与幂等 |
| M2 Key 池管理 | 管理端多 Key、优先级、状态机（含耗尽/重新启用）、明文查看 |
| M3 欠费自动切换 | 判定信号、切换重试、全部耗尽失败退款、并发、不切换路径 |
| M4 计费统一与模型目录 | 单轨计费、catalog 去 mine、默认模型 |
| M5 前端移除与全站回归 | 用户侧我的渠道/个人渠道全量清除 + 既有功能回归 |
| M6 安全 | Key 保护、越权、admin 边界 |

### 1.2 验收环境与账号矩阵

- 部署：测试环境全量部署（前端 + Express + T7 迁移已执行 + mock 上游服务可用）。
- 渠道矩阵：

| 渠道 | 协议 | 用途 |
|------|------|------|
| ToAPIs（平台） | toapis | 真实链路主回归 |
| mock 渠道 | openai_image（指向 mock stub） | M3 全部用例 |
| 火山（平台，可选） | volcengine_image | 协议抽查 |

- 账号矩阵：admin（M1/M2/M6）、userA（M3/M4/M5 主流程，积分 ≥ 100）、userB（M6 隔离）。

### 1.3 前置条件

1. T7 迁移已在**生产快照演练库**通过一轮（测试文档 §3.4 V-01~V-09）。
2. mock 渠道已配置并可按 §2.1 的 Key 行为表动态增删。
3. userA 已充值；平台生图模型定价完整。

## 2. M1 渠道固定化与存量迁移

| 用例 | 步骤 | 预期 | 级别 |
|---|---|---|---|
| M1-01 | 迁移后查库 | 用户渠道（owner_user_id 非空）行数 = 0；其 keys/models 关联行全无 | S |
| M1-02 | 迁移后查库 | 原主 Key priority=1、其余 priority=100；平台渠道/模型/Key/定价与迁移前基线逐项一致 | S |
| M1-03 | 迁移后查库 | `user_toapis_keys` 表不存在；`idx_api_provider_keys_primary` 不存在 | S |
| M1-04 | 原用户渠道下的历史任务打开详情/搜索 | 任务正常展示（channel_* 外键已置空，provider_code/model 快照可读） | S |
| M1-05 | 重启服务两次 | T7 标记命中、行数零变化（幂等） | S |
| M1-06 | 全新空库初始化 | 基线 schema 含 priority/exhausted_at、无 is_primary；种子 Key priority=1 | S |
| M1-07 | `GET/POST /api/my/*` 全组、`/api/me/toapis*`、`GET /api/admin/ai-config/user-providers` | 404（或过渡版 410），无业务副作用 | S |
| M1-08 | 迁移期间自动备份 | 备份文件生成、可独立打开校验 | S |
| M1-09 | `GET /api/me/quota` | 响应无 personalKeyCredits 字段，其余字段不受影响 | A |

## 3. M2 Key 池管理（管理端）

| 用例 | 步骤 | 预期 | 级别 |
|---|---|---|---|
| M2-01 | admin 打开某渠道 Key 管理 | Key 列表按优先级升序；列含名称/明文 Key/优先级/状态/最近检测；无「主 Key」概念 | S |
| M2-02 | 新增 Key（不填优先级） | 成功；优先级 = 当前最大+1（首个为 1）；明文可见可复制 | S |
| M2-03 | 新增/编辑 Key 优先级填 0、负数、非整数 | 400 校验拒绝 | S |
| M2-04 | 调整优先级（把备用 Key 改为 1） | 保存后排序变化；下一次调用出站用新优先级最高的 Key | S |
| M2-05 | 同优先级两个 Key | 选取稳定按录入先后（id 序），不随机 | A |
| M2-06 | 停用某 Key（switch） | 该 Key 不再被调用；渠道仍有可用 Key 时业务不中断 | S |
| M2-07 | 删除唯一 Key 后渠道级测试 | 测试返回「没有可用 Key」类明确错误 | A |
| M2-08 | 单 Key 测试连通 | 沿用正常（写最近检测时间与结果） | S |
| M2-09 | 渠道卡片信息 | 显示首个 Key hint + Key 总量；无可用 Key 时出现醒目警示 | A |
| M2-10 | Key 轮换（编辑换 Key 值） | 新值生效、最近检测结果清空（沿用） | S |

## 4. M3 欠费自动切换（mock 上游）

| 用例 | 场景 | 预期 | 级别 |
|---|---|---|---|
| M3-01 | mock：K1(优先级1)→402「余额不足」，K2(2)→正常；userA 提交生图 | **本次任务成功**；出站先 K1 后 K2；DB 中 K1=exhausted（含时间戳）、K2=active；用户端无失败痕迹 | S |
| M3-02 | mock：K1→400「insufficient quota」（文案变体） | 同 M3-01（文案判定路径） | S |
| M3-03 | mock：K1、K2 均欠费 | 任务 failed，errorCode=`ALL_KEYS_EXHAUSTED`，文案含「已耗尽或停用」；**全额退款流水**；两 Key 均 exhausted | S |
| M3-04 | mock：K1→401 Invalid key | 失败原因为上游 401；K1 **未被标记耗尽**（仍 active）；无第二次出站 | S |
| M3-05 | mock：K1→500 | 失败为普通上游错误（SUBMIT_FAILED/UPSTREAM_ERROR）；K1 未被标记；不切换 | S |
| M3-06 | 承接 M3-01：admin 对 K1「重新启用」 | K1 → active、耗尽标记清空；下一次提交出站重新用 K1（优先级最小） | S |
| M3-07 | 同步渠道（openai_image mock）同 M3-01 布置 | 结果与 M3-01 一致（runSyncTask 路径） | S |
| M3-08 | 画布文字 AI 节点，mock chat 同 M3-01 布置 | 调用成功；K1 被标耗尽；出站第二请求带 K2 | S |
| M3-09 | 10 并发提交，K1 同时欠费 | K1 恰好标记一次（exhausted_at 单值）；所有任务成功（经 K2）或明确失败退款；无卡死、无双扣 | S |
| M3-10 | 全部 Key 停用（disabled）后提交 | failed（`ALL_KEYS_EXHAUSTED` 文案含「停用」）+ 退款 | S |
| M3-11 | mock：K1→429「quota exceeded」 | 判定为耗尽并切换（白名单状态码） | A |
| M3-12 | 异步任务轮询期间 mock 返回 402（任务已在途） | 轮询异常容忍（任务不立即失败、不切换 Key）；终态由上游失败/超时清扫路径决定 | A |

## 8. 通过标准与回归结论

1. **S 级用例 100% 通过**方可发布；A 级允许 ≤ 2 项带条件通过（附修复计划）；B 级仅记录。
2. M3 中 M3-01 / M3-03 / M3-06（切换成功、全耗尽退款、重新启用）为核心能力三锚点，任一失败即整体阻断。
3. M5 回归中任一既有功能主流程失败即视为阻断（不论级别标注）。
4. 验收产出：用例执行记录表 + 缺陷清单（按测试文档 §4 分级）+ 迁移演练报告（测试文档 §3.4）。
