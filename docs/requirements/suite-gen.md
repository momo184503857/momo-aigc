# 成套生图与提示词专家 · 功能方案（suite-gen）

> 业务域代号：`suite-gen`。本文档是「空间叙事成套生图 + 提示词组装体系 + AI 提示词专家」三个功能的产品需求方案。
> 来源：从《女装电商生图工作台 V10.0》（本地单文件 HTML 工作台）迁移核心能力到 momoaigc 产品化体系。
> 配套文档：技术方案 `docs/design/suite-gen-tech.md`，验收标准 `docs/requirements/suite-gen-acceptance.md`。

---

## 1. 背景与目标

### 1.1 背景

运营侧现有一个本地工作台（单文件 HTML + 本地代理），沉淀了女装电商生图的完整方法论：

1. **成套生图**：一张服装图 → 自动匹配方案 → 生成同一场景 5 个机位的连续模特照（"一步一景"）。
2. **锁定式 Prompt 工程**：一套防 AI 翻车的锁定模板（服装还原/色彩锁/手部锁/场景真实性/季节植被等）+ 声明式组装。
3. **提示词专家**：4 种"拆图"玩法（18 项拆解 / 拆解融合 / 原图保真换脸换装 / 空间叙事衍生）。

该工作台仅限单机单人使用，无账号体系、无计费、无资产管理。本方案将其迁移到 momoaigc，向全部用户开放。

### 1.2 目标

| 目标 | 衡量标准 |
|------|---------|
| 成套生图可用 | 用户上传 1 张服装图，10 次点击内完成一次 5 张成套生成 |
| 资产双轨配置 | 管理员配置的主题/模特/模板全员可用；用户可自建私有资产 |
| Prompt 可解释可编辑 | 用户能看到 Prompt 的公共锁定部分与每张差异部分，可修改后再生 |
| 复用现有体系 | 生图走现有任务系统（积分计费、双模式 Key、OSS、作品库一键同款） |

### 1.3 非目标（V1 不做）

- 不做视频/多套系联动排期。
- 不做工作台的「服装平铺图」「批量 Prompt」页（其中平铺图 momoaigc 已有 `flat-pic` 功能）。
- 不做 seed 复现（ToAPIs 模型不支持 seed 参数）。
- 不做 AI 自动视觉拆解（18 项拆解 V1 维持"Canvas 提取 + 人工选择 + 规则推理"，多模态 LLM 拆解留作 V2 增强）。

## 2. 术语表

| 术语 | 定义 |
|------|------|
| 套系（Suite） | 一次成套生成的完整单元：1 个主题 × 5 个点位 = 5 张图 = 5 个生图任务 |
| 主题（Theme） | 一条空间动线定义，含 5 个点位描述（如"院外→中庭→池塘→廊桥→茶室"） |
| 赛道（Track） | 风格赛道（新中式/度假/都市等 7 种），锁定基调/发型/光影/配饰/手部姿态 |
| 模特人设（Persona） | 模特 DNA 文字描述 + 头像 + 指纹参考图（3 角度 + 5 五官特写，最多 8 张） |
| 锁定模板（Lock Template） | 可复用的 Prompt 约束片段（如【色彩锁定】【手部结构锁定】） |
| 点位（Point） | 套系中的第 N 张图，含场景描述、姿态、景别、人物站位 |
| 全局资产 | `owner_user_id = NULL` 的资产，管理员维护，全员可见可用 |
| 私有资产 | `owner_user_id = 某用户` 的资产，仅本人可见可用 |

## 3. 功能地图

```
momoaigc 主站
├─ 成套生图（新路由 /suite-gen）────────────── 功能A
│   ① 上传服装图 → ② 智能匹配 → ③ 微调选择 → ④ 服装细节
│   → ⑤ Prompt 预览编辑 → ⑥ 提交 5 任务 → ⑦ 套系管理/重生成/发布作品
│
├─ 提示词专家（新路由 /expert）─────────────── 功能C
│   ├─ Tab1 原版拆解(18项)  → 存入我的提示词库，可发布到提示词卡片社区
│   ├─ Tab2 拆解融合        → 单张生成（复用任务系统）
│   ├─ Tab3 原图保真换脸换装 → 单张生成
│   └─ Tab4 空间叙事衍生    → 生成套系草稿，跳转功能A继续
│
├─ 提示词工坊（现有 /prompt-workshop）──────── 功能B 落点之一
│   └─ 锁定模板卡片化：管理员发布官方锁定模板卡片，用户复用
│
└─ 管理后台（现有 /admin）─────────────────── 资产管理
    └─ 成套生图资产管理：主题库/赛道库/模特人设/锁定模板/服装特征/拆解知识
```

三个功能的关系：**功能B（组装引擎）是地基**，功能A和功能C的所有 Prompt 产出都经过它；功能A和功能C共享资产库与生图链路。

## 4. 资产体系与权限模型（核心设计）

### 4.1 资产类型总表

| 资产 | 内容 | 默认种子数据（来自工作台迁移） | 用户可否自建 |
|------|------|------------------------------|-------------|
| 主题库 | 名称、所属赛道、季节(春夏/秋冬/全部)、动线路径、5 点位描述 | 100 套内置主题 | ✅ |
| 赛道库 | 名称、基调、发型妆造、光影、配饰方向、手部姿态 | 7 大赛道（新中式/度假/都市/极简/法式/成熟优雅/通勤职场） | ✅ |
| 模特人设 | 名称、头像、DNA 描述、指纹参考图（≤8 张） | 1 个示例人设（M1 贝尔，头像+DNA 文字） | ✅ |
| 锁定模板 | 模板键、分组、排序、内容、启用条件、适用模型 | 工作台全部锁定模板（约 20 条，见 5.4） | ✅ |
| 服装特征 | 分组（风格/版型/面料/设计元素/自带配饰）、名称、匹配关键词 | 工作台 FEATURES 全量（5 组约 30 项） | ✅ |
| 拆解知识 | 18 项字段选项库 + 6 条推理规则 | 工作台 KNOWLEDGE + REASON_RULES 全量 | ✅ |

### 4.2 双轨权限规则

| 操作 | 全局资产（管理员建的） | 私有资产（用户自己建的） |
|------|----------------------|------------------------|
| 浏览/使用 | 所有人 | 仅本人 |
| 新建 | 仅管理员（后台）+ 用户可"另存为私有副本" | 所有人 |
| 编辑/删除 | 仅管理员 | 仅本人 |
| 智能匹配推荐范围 | 默认参与 | 默认参与（可开关"匹配只用我的"） |

规则细节：

1. **打开即用**：新用户进入成套生图页，全局资产（100 主题 + 7 赛道 + 锁定模板）直接可选可生成，无需任何配置。
2. **另存为副本**：用户对全局资产不满意时，可"复制为我的"生成私有副本再改，不影响其他人。
3. **引用快照**：套系/任务提交时对所用资产做**快照存档**（存当时的完整内容），此后资产被管理员修改或删除，不影响历史套系复现与作品库一键同款。
4. **使用计数**：全局资产记录 `use_count`，管理员后台按热度排序，为运营提供数据。

### 4.3 管理员后台入口

管理后台新增「成套生图资产」页，6 个 Tab（主题/赛道/模特人设/锁定模板/服装特征/拆解知识），统一交互：列表 + 搜索 + 新建/编辑弹窗 + 启用停用。锁定模板额外支持"按模型分版本"（同一模板键在 gpt-image-2 与 gemini 下可有不同话术）。

## 5. 功能A：成套生图（主流程）

### 5.1 用户故事

> 作为一个女装电商运营，我上传一张服装图，系统推荐整套方案，我确认后一键得到 5 张同一场景、机位连续的模特照，可以直接上架详情页。

### 5.2 页面流程（向导式，7 步）

```
①上传服装 → ②智能匹配 → ③方案微调 → ④服装细节 → ⑤Prompt预览 → ⑥生成 → ⑦套系管理
```

**① 上传服装参考图**
- 主图：正面全身/七分服装图，1 张，必填。前端 Canvas 自动提取主色（HEX + 名称）与亮度。
- 细节图：袖口/印花/裙摆/面料/领口等，最多 6 张，选填；生成时排在主图之后作为辅助参考。
- 服装特征速选：风格/版型/面料/设计元素/自带配饰 五组多选 Chips（数据来自服装特征库）。
- 可选：从「我的图库」（template_images）直接选用。

**② 智能匹配整套方案**
- 规则引擎（纯前端）：主色 + 特征标签 → 加权打分 → 推荐「3 个赛道 × 2 个主题」共 6 个候选卡片。
- 每张卡片展示：赛道基调缩略、主题动线示意（5 点位横条）、推荐理由（命中了哪些特征）。
- 操作：点选应用 / 换赛道 / 换主题 / 随机重匹配。
- 模特发型锁定：换赛道/换主题时保留用户手动选过的模特与发型。

**③ 方案微调**
- 模特人设（卡片选择，含头像与 DNA 摘要；可"管理我的模特"）、发型妆造（跟随人设或手动覆盖）、赛道、季节（春夏/秋冬，过滤主题库）、主题。
- 所选项均来自资产库，支持切换"全部 / 仅我的"范围。

**④ 服装细节描述（四层结构）**
- 版型轮廓 / 面料层次 / 结构细节 / 专属元素 四个文本域 + 印花描述 + 自带配饰清单。
- 根据特征速选自动预填建议文案，用户可改。
- 目的：把"防止 AI 丢配饰、简化复杂版型"的方法论固化到表单。

**⑤ Prompt 预览与编辑**
- 左侧：公共锁定部分（分组折叠：人物/服装/场景/光影/负面约束），每条可单独开关、可编辑文本。
- 右侧：5 个点位的差异部分（点位场景、姿态、景别、站位），逐张可编辑。
- 底部实时预览每张最终 Prompt 全文（复制按钮）。
- 模板开关只影响本次套系，可"把我的修改存为私有锁定模板"（进入 4.1 资产体系）。

**⑥ 提交生成**
- 显示确认面板：模型、分辨率、比例（默认 3:4）、张数 = 5、**积分预估 = 单价 × 5**。
- 点击后串行提交 5 个任务（点位 1→5 顺序），每个任务携带同一组参考图 + 各自点位 Prompt。
- 提交过程展示进度（x/5 已提交），失败任务不阻塞后续点位提交。

**⑦ 套系管理**
- 任务列表（现有 TaskList）新增"套系"分组视图：套系卡片显示 5 个点位缩略图墙、整体状态（生成中/x 完成/失败）、失败点位"重新生成"。
- 套系完成后支持：单张下载 / 全部下载（打包 zip）/ 全部发布到作品库（5 张作品携带同一 prompt_segments 快照，他人"一键同款"直接复现整套）。
- 套系记录可从「成套生图 → 历史套系」回看，重进编辑再生成。

### 5.3 智能匹配规则（V1 简化版）

```
输入：主色(HEX→色系) + 特征标签集
打分：
  赛道分 = Σ(特征标签 × 赛道关键词命中) × 0.6 + 色系倾向 × 0.4
  主题分 = 赛道分 × 0.5 + 季节过滤后随机扰动 × 0.3 + use_count 归一化 × 0.2
输出：赛道 Top3 × 各自主题 Top2
```

规则数据（特征→赛道关键词映射、色系倾向表）放拆解知识库，管理员可调。

### 5.4 锁定模板清单（功能B 资产，成套生图默认启用）

| 分组 | 模板键 | 内容摘要 | 默认 |
|------|--------|---------|------|
| quality | base.lock | 8K 竖版电商图、四周留白、全身机位 | 开 |
| garment | garment.restore | 服装 100% 还原（版型/面料/色彩/印花） | 开 |
| garment | garment.acc-lock | 服装自带配饰必须保留，禁止删减更换 | 开 |
| garment | garment.color-lock | 禁止自动调色/色相漂移/饱和度改变 | 开 |
| identity | identity.single | 单人构图强制（禁第二人/人群/镜像分身） | 开 |
| identity | identity.real-skin | 真实感去 AI 化（拒绝磨皮塑料脸） | 开 |
| identity | identity.real-hair | 发丝写实（拒绝假发感） | 开 |
| identity | identity.real-makeup | 妆容写实（拒绝浮粉卡纹） | 开 |
| identity | identity.dna | 模特 DNA 注入（人设字段动态填充） | 开 |
| identity | identity.fingerprint | 指纹库多图身份锚定（有指纹图时启用） | 条件 |
| scene | scene.unify | 全套统一：妆发/光影/色调禁漂移 | 开 |
| scene | scene.continuity | 空间连续性：5 点位一步一景说明 | 开 |
| negative | neg.scene-reality | 场景真实性约束（按空间类型的道具白名单） | 开 |
| negative | neg.outdoor | 户外硬约束（禁室内元素混入） | 条件 |
| negative | neg.flora | 季节植被合理性（花卉与季节/空间匹配） | 条件 |
| negative | neg.hand | 手部结构锁定（禁六指/扭曲） | 开 |
| pose | pose.progress | 点位递进（景别/姿态/站位逐级变化） | 开 |
| camera | camera.composition | 机位构图（本张差异部分引用） | 开 |
| quality | quality.post | 后期质感（商业实拍基底） | 开 |

"条件"类模板由组装引擎按上下文自动判断（如户外主题才注入 neg.outdoor）。

## 6. 功能B：提示词组装体系

### 6.1 定位

不是一个独立页面，而是**横切的基础能力**：成套生图、提示词专家、提示词工坊三处共用。

### 6.2 组装模型

```
一条完整 Prompt = Σ 开启的模板条目（按 group+order 排序）
                + 上下文动态填充（模特DNA/赛道字段/主题点位/服装四层）
                + 每张差异部分（点位/场景/姿态/机位）

模板条目 = { key, group, order, content, condKind?, enabled }
上下文   = { persona, track, theme, pointIndex, garment, features, model }
```

与现有六层结构（主体/风格/场景/光影/构图/画质）的关系：六层是**自由生图**的人工填写模型，保持不变；锁定模板体系是**功能生图**的程序组装模型，两者通过 `prompt_segments` 统一落库（segments JSON 中加 `type: 'suite' | 'expert' | 'workshop'` 区分）。

### 6.3 与提示词工坊的融合

- 管理员可将任一锁定模板一键「发布为官方提示词卡片」（prompt_cards，is_official=1），进入社区复用/点赞体系。
- 用户在工坊复用的卡片，可在成套生图/专家页的"我的模板"里引用（私有锁定模板自动同步为工坊私有卡片）。

### 6.4 按模型分版本话术

同一模板键在不同模型下允许不同 content（工作台话术为豆包 Seedream 调教，迁移时需为 gpt-image-2 / gemini 各出一版基线话术，由管理员在后台持续调优）。组装时按当前任务模型取对应版本，无版本时回落默认。

## 7. 功能C：AI 提示词专家（4 玩法）

统一入口 `/expert`，四 Tab，共享底部「生成模式」区（模型/分辨率/比例 + 直连生成按钮，复用现有任务提交）。

### 7.1 Tab1 原版拆解（18 项）

- 上传 1 张电商主图 → Canvas 自动提取主色/亮度/构图分布，自动填入对应项。
- 18 项拆解表单：核心主题定位、场景、道具、空间、脸型、表情、妆容发型、姿态、肢体动作、配饰、光影、机位、镜头、构图、质感、参数、服装描述、氛围 —— 每项下拉选项来自拆解知识库。
- **智能推理补全**：填写"核心主题"后，按 6 条关键词规则（新中式/法式/极简/成熟/甜美/宴会）自动补全空项；未命中规则时按用户历史拆解中相似主题补全。
- 生成 1 条完整 Prompt → 可复制 / **存入我的提示词库**（prompt_library，结构化 segments 快照）/ 应用到自由生图 / 发布到提示词卡片社区。
- 反馈闭环：对推理结果标记"精准/需修正"，精准字段在下次同主题推理中优先保留（存用户级反馈数据）。

### 7.2 Tab2 拆解融合

- 三个图槽：电商主图（场景基准 + 最高权重 i2i 锚定，必填）、模特人设（工作台人设或上传头像图，选填）、服装参考图（必填）。
- 一键生成融合 Prompt（模板来自锁定模板库的 fusion 分组）→ 直连生成 1 张。
- 定位：现有「换衣服」功能的场景增强版——场景跟主图、脸跟人设、衣服跟参考图。

### 7.3 Tab3 原图保真换脸换装

- 四个图槽：优质主图（**绝对基底**，必填）、模特头像（人设模板或上传，选填）、发型参考图（上传或素材库，选填）、服装参考图（选填）。
- 核心约束模板（保真分组）："场景/光影/姿态/构图/色调 100% 保留，仅替换人脸/发型/服装，重拍而非换图"。
- 生成 1~4 张（n 可选）供挑选。

### 7.4 Tab4 空间叙事衍生

- 上传 1 张优质主图 → 填写/推理空间拆解（空间类型、动线逻辑、可衍生点位）→ 系统生成 1 个**衍生主题草稿**（含 5 点位）。
- 主题草稿可：存入私有主题库 / 直接"生成套系"（跳转功能A ⑤，带上主图与草稿）。
- 定位：把任意一张好图变成一个可复用的成套主题，形成"看图→拆解→成套"的闭环。

## 8. 计费与风控

| 场景 | 规则 |
|------|------|
| 成套生图 | 5 任务 × 模型单价，提交前明示预估总额；余额不足提示充值/换模型 |
| 专家玩法 | 单任务计费，同现有功能 |
| 失败退费 | 沿用现有"失败不扣费"规则，套系内单点失败自动退该点 |
| 频控 | 沿用现有任务级频控；单用户并发生成套系数 ≤ 2（防 10 连发打爆配额） |

## 9. 解耦与复用原则（对应用的第二条要求）

1. **资产即数据**：所有知识/资产入库（全局+私有双轨），前端零硬编码；换一套主题库即是另一个行业版本。
2. **一套资产 CRUD 通用层**：6 类资产共用同一后端路由工厂与前端 `useAssetLibrary` 组合式函数，新增资产类型只需声明配置。
3. **组装引擎纯函数**：promptEngine 零 UI/网络依赖，可单测、可在任何页面调用。
4. **生图统一走 imageGeneration 服务**：不新开生图通道，自动继承双模式 Key、积分、OSS、轮询、失败退费。
5. **UI 组件化**：图槽上传复用 ImageSlotUpload、资产选择器统一 AssetPicker、任务展示复用 TaskList/TaskDetailDialog；新组件（ThemeCard/PersonaPicker/GarmentDetailForm/PromptPreview/SuiteTaskGroup）均不耦合具体页面。
