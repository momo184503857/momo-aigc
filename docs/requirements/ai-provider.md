# AI 接入体系重构 · 功能方案（ai-provider）

> 业务域代号：`ai-provider`。本文档是「多渠道 AI 接入体系重构」的产品需求方案。
> 核心内容：生图/文字模型的多渠道（Provider）接入、平台渠道积分计价配置化、用户自建渠道、任务体系与服务端编排改造。
> 配套文档：技术方案 `docs/design/ai-provider-tech.md`，验收标准 `docs/requirements/ai-provider-acceptance.md`，迁移与上线 `docs/design/ai-provider-migration.md`。
> **修订提示（2026-08-20）**：用户自建渠道体系将由《固定渠道与多 Key 轮换》方案（`docs/requirements/fixed-channels.md`，规划中）整体取代——本文的 FR5（我的渠道）、D7/D8/D9、S1/S3 届时废止；渠道 Key 管理由「唯一主 Key」升级为「多 Key 优先级池 + 欠费自动切换」。在该方案实施前，本文仍为现行架构的规格来源。

## 1. 背景与目标

### 1.1 现状问题

当前 AI 接入完全绑定 ToAPIs 一家，且多处硬编码：

| # | 问题 | 现状位置 |
|---|------|---------|
| P1 | 上游地址硬编码 | `server/src/utils/toapis.ts` 的 `BASE_URL = 'https://toapis.com'` |
| P2 | 模型清单与能力（分辨率/宽高比/参考图上限）硬编码在前端 | `src/types/adapter.ts` 的 `MODELS` 数组 |
| P3 | 积分定价前后端双真源、手动同步（已知技术债，`docs/todo.md` 有记录） | `server/src/utils/pricing.ts` + 前端 `MODELS[].pricing` |
| P4 | 业务任务号绑定渠道任务号 | `generation_tasks.toapis_task_id`（轮询、转存、买家秀刷新恢复轮询、下载命名、后台搜索全用它） |
| P5 | 个人 Key 仅支持 ToAPIs 一家 | `user_toapis_keys` 单渠道单行表 + `resolveUserApiKey()` |
| P6 | 前端编排生图流程，多渠道的同步/异步差异无法收敛 | `src/services/imageGeneration.ts` + `useTaskManager.ts` |
| P7 | 文字模型（画布文字 AI 节点）直连 ToAPIs，游离在 provider 体系外 | `TEXT_MODELS` + `canvas-ai.ts` |
| P8 | 已有识图用 provider 三表体系（api_providers/ai_models/api_provider_keys），但生图未接入，`supports_image_gen` 字段闲置 | `server/src/providers/` |

### 1.2 目标

| 目标 | 衡量标准 |
|------|---------|
| 多渠道接入 | 管理员不改代码即可新增生图/文字渠道（base_url + key + 协议模板），第一期支持 ToAPIs、火山引擎（豆包 Seedream）、通用 OpenAI 兼容中转站 |
| 定价配置化 | 积分定价只在管理后台配置一处，前后端共用同一真源；按渠道×模型×分辨率定价 |
| 用户自渠道 | 用户可自建渠道（协议模板 + base_url + key）、自加模型，仅自己可见，生图不扣积分 |
| 任务体系解耦 | 业务任务号由服务端生成（内部任务号），渠道任务号降级为普通字段；同步/异步渠道对前端体验一致 |
| 服务端编排 | 提交、轮询、结果转存、扣费/退款全部收敛到服务端，前端只面对统一任务接口 |
| 存量无感升级 | 历史任务、现有共享/个人 ToAPIs Key 平滑迁移，用户无感 |

### 1.3 非目标（本期不做）

- 不做渠道路由自动化（自动选渠道、故障切换、按价格择优）——用户手动选择渠道和模型。
- 不做按宽高比/生成数量的阶梯计价（仅渠道×模型×分辨率）。
- 不做用户渠道的平台服务费（用户渠道完全不计积分）。
- 不做识图体系改造（`providers/` 识图适配器与默认识图模型配置维持现状，仅共用渠道表结构）。
- 不做渠道级用量配额/限流（后续演进）。
- 不做 Gemini 原生协议、Midjourney、Replicate 等更多协议（架构预留，后续按需加适配器）。

## 2. 术语表

| 术语 | 定义 |
|------|------|
| 渠道（Provider） | 一个 AI 服务接入点 = base_url + 协议适配器 + Key。分**平台渠道**（管理员配置，owner 为空）与**用户渠道**（用户自建，owner=某用户） |
| 协议模板 / 适配器（Adapter） | 渠道的协议类型，决定请求/响应格式与调用方式。第一期：`toapis`（异步任务式）、`openai_image`（OpenAI 兼容生图，同步）、`volcengine_image`（火山 Seedream，同步）、`openai_compat`（文字/识图，已有） |
| 逻辑模型（Logical Model） | 平台定义的"标准模型"（如 gpt-image-2），承载共享能力定义：分辨率清单、宽高比矩阵、参考图上限、提示词字数上限 |
| 渠道模型（Channel Model / 映射） | 渠道下的模型条目，关联一个逻辑模型，承载渠道差异：该渠道的模型名（model_id）、参数能力覆盖、积分定价 |
| 平台模型 | 平台渠道下的渠道模型，走积分计费 |
| 我的模型 | 用户渠道下的渠道模型，不扣积分，仅本人可见 |
| 内部任务号（task_no） | 服务端生成的业务任务号（`gen-YYYYMMDDHHRRRR`，北京时间年月日时+4位随机数），对外展示/搜索/下载命名的唯一键 |
| 渠道任务号（provider_task_id） | 异步渠道（ToAPIs）返回的上游任务号；服务端轮询用，并随任务返回在任务历史/详情中展示（同步渠道为空） |
| 同步渠道 / 异步渠道 | 同步渠道提交后直接返回图片（OpenAI 兼容、Seedream）；异步渠道返回任务号需轮询（ToAPIs） |

## 5. 功能需求

### FR1 平台渠道管理（管理员）

**渠道 = base_url + 协议适配器 + 主 Key。**

1. 渠道列表：名称、标识 code、协议模板（下拉，来自适配器注册表）、base_url、模型数、主 Key 脱敏 hint、状态（active/disabled）、备注。沿用现有「AI 服务商配置」页的渠道卡片与 Tab 结构。
2. 渠道 CRUD：新建/编辑/删除（删除校验：渠道下有模型时需级联确认）；停用渠道后其下模型在模型目录中立即不可选。
3. Key 管理：沿用现有"一渠道一把主 Key"机制（新增/轮换/停用/测试），AES-256-GCM 加密存储，仅脱敏 hint 回显。
4. 测试连通：按协议模板执行对应探测，展示结果与延迟。
5. 协议模板第一期清单：`toapis`（异步）、`openai_image`（同步）、`volcengine_image`（同步）、`openai_compat`（文字/识图，已有）。一个渠道只能选一种协议。

### FR2 逻辑模型（代码内置，管理员仅可改显示名）

1. 逻辑模型 = 标准模型抽象，字段：code（唯一，如 `gpt-image-2`）、显示名、类型（image/text）、默认能力定义。
2. **逻辑模型清单由平台代码定义**（`server/src/db/logicalModels.ts`，唯一事实源）：code / 类型 / 能力定义 / 状态均以代码为准，服务启动时幂等同步进 `ai_logical_models`（显示名与备注不动；清单外且无渠道模型关联的行清除）。新增/调整逻辑模型 = 改代码后重启，管理端不提供新增/删除/能力编辑（POST / DELETE 返回 410，PATCH 仅接受显示名）。
3. 能力定义内容：分辨率清单（如 512/1K/2K/4K）、每分辨率下的可用宽高比矩阵、最大参考图数量、最大提示词字数。
4. 用途：所有关联该逻辑模型的渠道模型**共享能力定义**（改一处全渠道生效）；渠道模型可用"能力覆盖"裁剪（只能收窄，不能超出）。
5. 内置清单：4 个生图模型（gpt-image-2 / gemini-3-pro-image-preview / gemini-3.1-flash-image-preview / gemini-2.5-flash-image-preview）+ 3 个文字模型（gpt-5.5 / gemini-3-flash / gemini-3.1-flash-lite），能力取自现状硬编码值。

### FR3 渠道模型与定价管理（管理员）

1. 渠道模型 = 渠道下的模型条目：所属渠道、**渠道模型名**（发给上游的 model 字符串，同一逻辑模型在不同渠道可不同名）、关联逻辑模型（平台侧必填）、能力覆盖（可选，裁剪逻辑模型能力）、定价、启停。
2. 定价：按能力中每个分辨率配置积分单价（如 gpt-image-2@ToAPIs：1K=3 / 2K=4 / 4K=5）。平台生图模型保存时定价必填（S6）。
3. 生成数量 n 的费用 = 单价 × n（沿用现状口径）。
4. 文字模型：渠道模型标记 `supports_chat`，无定价（文字调用暂不计费，沿用现状）。
5. 现有"支持识图/支持生图"勾选保留；生图模型必须关联逻辑模型。

### FR4 积分计费规则

1. **计费对象**：仅平台渠道模型。用户渠道模型生图费用为 0（D8）。
2. **预扣**：任务提交时按 所选渠道模型定价[分辨率] × n 预扣，积分不足返回 402（沿用现有交互：提示积分不足、任务不创建）。
3. **退款**：任务进入 failed（提交失败/上游失败/超时/清扫）自动全额退款并写 refund 流水；completed 后不再退（防套退，沿用现状）。
4. **流水**：沿用 points_transactions（reason=generation / refund），关联内部任务。
5. **展示**：生图表单按钮展示当前价格（从模型目录取），我的渠道模型显示"个人渠道 · 不扣积分"；「计费说明」页从模型目录动态渲染，不再硬编码。
6. **统计口径**：「我的额度」页与后台统计中，平台消耗 = 积分流水；个人渠道消耗为参考值（按所选渠道模型定价折算，无定价则不计）。
7. 换算关系沿用：1 积分 = ¥0.035（`YUAN_PER_CREDIT`）。

### FR5 我的渠道（用户自建）

1. 渠道 CRUD：名称、协议模板（与平台一致的四种）、base_url、Key（加密存储、脱敏回显、可轮换）、测试连通、启停。仅本人可见（S1：管理员后台只读可见）。
2. 渠道下自加模型：填渠道模型名；能力二选一——**引用逻辑模型模板**（只读继承平台逻辑模型能力，可裁剪）或**完全自定义**（分辨率/宽高比矩阵/参考图上限/提示词上限）。
3. 用户渠道模型无定价、不扣积分；不进入其他用户的模型目录。
4. toapis 协议的用户渠道支持余额查询（沿用现有余额轮询交互与间隔配置，S3）。
5. 安全（S7）：base_url 仅 http/https、拒绝私网 IP/localhost；请求由服务端代理发出（浏览器永不直连上游）。

### FR6 模型选择器与能力联动

1. 生图表单的模型下拉按**渠道分组**：平台渠道组在前（组名=渠道名），「我的渠道」组在后并带"个人"标签。
2. 选中模型后联动：分辨率选项 = 该渠道模型生效能力；宽高比 = 所选分辨率下的矩阵；参考图数量上限；提示词字数上限；价格展示（平台模型）或"个人渠道"标记。
3. 切换模型时若当前分辨率/宽高比不兼容则重置为该模型默认值（沿用现有联动规则）。
4. 选中我的渠道模型 = 走个人渠道（不扣积分、跳过余额预检）；选中平台模型 = 平台积分结算。**不再有全局"平台/个人 Key"开关**（S4）。

### FR7 生图任务体验（服务端编排后的用户可见行为）

1. 提交：前端上传参考图到 OSS（沿用现状）→ 调统一提交接口（渠道模型 + 参数）→ 返回内部任务号。同步/异步渠道对前端无差异。
2. 轮询：前端每 4 秒查询任务状态（节奏与现状一致）；进度、失败原因展示沿用。
3. 结果：全渠道统一转存平台 OSS（D12），任务详情展示 OSS 永久 URL；转存失败保留原始 URL 并支持"重新加载"（S5）。
4. 任务号：任务列表/详情/结果页展示与复制 task_no；下载文件名使用 task_no；后台活动日志支持按 task_no 搜索。
5. 重试：沿用"按任务参数重新提交"模式；转存失败重试沿用。
6. 历史任务：升级前的任务正常展示（渠道标记 toapis，含旧渠道任务号）。

### FR8 文字模型迁移（画布文字 AI 节点）

1. 画布文字 AI 节点的模型选择改为模型目录（kind=text，按渠道分组），不再使用前端硬编码 TEXT_MODELS。
2. 调用走服务端 provider 代理（按所选渠道模型解析渠道与 Key），计费维持现状（不计积分）。
3. 识图链路（成套生图 AI 识别、后台识图模型配置）不变。

### FR9 存量无感迁移（D10）

升级后首次启动自动完成，用户无感：

1. ToAPIs 共享 Key（system_config.toapis_api_key）→ toapis 平台渠道的主 Key。
2. 现有 4 生图 + 3 文字模型 → toapis 平台渠道下的渠道模型（关联对应逻辑模型，定价取自现状 pricing.ts）。
3. 每个用户的个人 ToAPIs Key（user_toapis_keys）→ 该用户的 toapis 用户渠道 + Key + 4 个生图渠道模型；原"启用个人 Key"的用户升级后直接可用。
4. 历史 generation_tasks：回填渠道=toapis、渠道任务号=原 toapis_task_id、生成内部任务号；历史任务展示/搜索/下载不受影响。
5. 原「平台积分 / 个人 Key」全局开关退役；升级后用户在模型下拉里选"我的渠道"下的模型即等价于原个人 Key 模式。

### FR10 管理端与报表

1. 任务管理/活动流水：展示 task_no + 渠道 + 渠道模型名；搜索支持 task_no（兼容旧渠道任务号）。
2. 统计：积分消耗口径不变（SUM points_cost）；渠道维度报表为后续增强，非本期硬性范围。
3. 用户渠道只读列表（S1）：渠道名/协议/base_url/模型数/状态/所属用户，不含 Key 明文。

## 6. 关键用户旅程

### 6.1 管理员：接入一个新渠道（以 OpenAI 兼容中转站为例）

1. 管理后台 →「配置」→ 新增服务商：名称"中转站B"、协议模板 `openai_image`、base_url、保存。
2. Key 管理：录入主 Key → 点"测试连通" → 显示成功与延迟。
3. 模型管理 → 新增模型：渠道模型名 `gpt-4o-image`（该渠道的叫法）、关联逻辑模型 `gpt-image-2`（继承能力）、按分辨率定价 1K=2.8 / 2K=3.9 / 4K=4.9 → 保存（定价必填校验）。
4. 用户侧生图表单立即可见：渠道组"中转站B" → gpt-image-2（能力继承逻辑模型，价格为本渠道定价）。

### 6.2 用户：自建渠道生图

1. 「我的渠道」页 → 新建渠道：选协议模板（openai_image / toapis / volcengine_image / openai_compat）、base_url、Key → 测试连通 → 启用。
2. 渠道下添加模型：填上游模型名，能力引用逻辑模型 `gemini-3.1-flash-image-preview` 模板并裁剪掉 4K。
3. 回到生图表单：模型下拉「我的渠道」分组选中该模型 → 按钮显示"个人渠道 · 不扣积分" → 生成 → 流程与平台模型完全一致。

### 6.3 普通用户：平台模型生图（计费）

1. 模型下拉选平台渠道模型 → 按钮显示价格（如 "3.0 积分"）。
2. 提交：积分不足 → 402 提示、任务不创建；充足 → 预扣、任务进入列表、4s 轮询。
3. 失败：自动全额退款，任务标 failed 并展示原因；「我的额度」流水可见 generation/refund 记录。

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 安全 | Key 全程 AES-256-GCM 加密存储、明文永不回传（含管理端/用户端/日志）；用户渠道 base_url 做 SSRF 基本防护；所有上游调用由服务端发出 |
| 性能 | 提交接口 P95 < 3s（不含同步渠道上游生图耗时，该耗时由后台吸收）；轮询端点单次查询轻量；转存防并发重复 |
| 兼容 | 历史任务/作品/积分流水/统计报表升级后语义不变；works 发布、买家秀、批量工具等下游不感知渠道差异 |
| 可靠 | 服务重启不丢任务：异步渠道凭渠道任务号继续轮询；同步渠道在途任务清扫标失败并退款 |
| UI 约束 | 新页面遵循 `--momo-*` token 体系与 `useUiFeedback`，Element Plus 主题映射（见 docs/ui/ui-design-guidelines.md） |
