# 逻辑模型渠道拖拽优先路由

> 确认日期：2026-09-11

## Objective

管理员编辑逻辑模型时，能够查看该逻辑模型已接入的全部渠道模型，通过拖拽维护全局路由顺序。图片生成严格按管理员保存的顺序逐渠道尝试，不再按成本价选择渠道。

## Confirmed behavior

- 路由顺序按逻辑模型维护，1K/2K/4K 共用同一顺序。
- 拖拽顺序完全取代成本排序；成本价仅保留为管理诊断信息。
- 每个关联渠道模型可在编辑弹窗中单独设置是否“参与路由”；关闭只影响当前逻辑模型，不改变渠道或渠道模型的全局状态。
- 已关闭路由、全局停用、无可用 Key 或能力不匹配的渠道仍显示在编辑列表中，执行时自动跳过。
- 当前渠道失败后按顺序尝试下一渠道；全部失败保持现有退款和 `ROUTES_EXHAUSTED` 语义。
- 保存采用显式“保存路由配置”按钮，不做拖拽或开关变更后的自动保存。
- 新增渠道模型默认排在已有明确顺序之后。
- 同一渠道如果误配多个关联渠道模型，只取顺序最靠前且能力匹配的一项；一个任务不会重复尝试同一渠道。

## Technical scope

- SQLite `ai_models` 增加 `route_priority`，数值越小越优先。
- 未显式排序的历史数据使用相同默认优先级，并以渠道模型 ID 保持确定性顺序；不再以成本作为兜底排序。
- SQLite `ai_models` 增加 `route_enabled`，默认启用，用于控制渠道模型是否参与所属逻辑模型的路由。
- 管理 API 返回逻辑模型关联渠道清单，并提供原子化顺序与参与状态保存接口。
- 管理端逻辑模型列表增加编辑弹窗，展示渠道、模型、状态、Key 可用性与成本，支持参与路由开关、鼠标拖拽和键盘上移/下移。

## Commands

- 类型与前后端检查：`npm run check`
- 生产构建：`npm run build`
- 后端构建：`npm run build:server`
- 开发服务：`npm run dev`、`npm run dev:server`

## Boundaries

- Always: 使用 `--momo-*` 设计 token；使用 `useUiFeedback`；服务端原子校验并保存完整顺序；保留失败退款与尝试记录。
- Ask first: 修改统一售卖价、成本价或 Key 优先级；部署生产；提交或推送 Git。
- Never: 把 API Key 写入跟踪文件；按成本覆盖管理员拖拽顺序；提交工作区已有的无关修改。

## Success criteria

1. 编辑任一生图逻辑模型可看到全部关联渠道模型和可用状态。
2. 拖拽或切换参与路由状态后点击保存，刷新页面配置保持不变。
3. 生成任务严格选择首个已开启参与路由、状态和能力均可用的渠道，不考虑成本高低。
4. 首选渠道失败后按保存顺序切换下一渠道。
5. 全部失败仍全额退款，并保留每次渠道尝试记录。
6. 文字逻辑模型无渠道路由编辑入口。
7. `npm run check` 与 `npm run build` 通过。
